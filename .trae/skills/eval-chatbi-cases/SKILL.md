# ChatBI 问数质量评测

给已经在本机跑起来的 ChatBI 测问数质量，不是测页面好不好用。

流程：用户调用时指定一份评测文档 → 读出每一条用例 → 直接打后端 HTTP/SSE 接口 → 按 rubric.md 硬条件判过/不过 → 写出汇总报告。

## 何时用 / 不用

- 用：用户说「跑问数评测」「按这份文档打分」「出评测报告」。
- 不用：正在写代码、改 SDD、改评测文档、改打分规则、只在浏览器里点功能。

## 前置检查（缺一就停下问用户，不要猜）

1. 本次使用的评测文档路径。用户没指定就问；不要默认锁死 docs/测例.md，也不要自己另出一套题。
2. 后端已启动。默认 http://127.0.0.1:8000，用户另给了地址就用用户的。
3. GET /api/v1/health 通过：checks.db=ok 且 checks.llm=ok（整体 status=ok；embedding=unconfigured 不卡，检索会走 lexical 降级）。

否则不要开跑。

## 评测文档怎么读

- 用户指定哪份就读哪份；不增删、不改写问句，也不要去改那份文档。
- 每条用例读：id、用户问题（原句）、期望结果类型。期望类型常见取值：表 / 图 / 解读 / 表+解读 / 追问（澄清） / 拒答。
- 文档里若还有考察点、补充说明、指定澄清选项，当作该条的额外硬条件。
- 缺「用户问题」或「期望结果类型」列就停下来问用户，不要猜；缺其它列就按已有列读。

## 执行步骤

1. 读本目录的 rubric.md。
2. 健康检查（见前置）。
3. 按文档逐条：POST /api/v1/chat/turns，question 用该条用户问题原句；不带 session_id 自动建会话，多轮/承接类沿用上一条返回的 session_id。
4. GET /api/v1/chat/turns/{turn_id}/events 收 SSE 到终态帧（零或多个 stage 帧后恰一终态帧 → done）。
5. 期望为追问/澄清的：ask → clarify 两步完成，按 rubric 与该条文档执行；文档没写选哪个口径就问用户。
6. 单条超时从宽（问数可能几十秒）。一条失败记下 HTTP 状态、body 摘要或 error/rejection 帧，继续下一条，不要中断整场。
7. 硬条件全过才算该条通过；软条件只进报告备注。
8. 写报告。条数以这份文档为准，不要写死 15 条。

## 禁止

- 改代码 / 改 YAML 字典 / 改 SDD / 改用户指定的评测文档 / 改 rubric.md
- 手写答案 SQL
- 打开浏览器测前端
- 把 LLM/EMB 配置换成假实现、补表、为过题改口径
- 测报表、登录、Compose

## 报告

路径：开发记录/评测报告-YYYYMMDD.md

- 开头：用了哪份评测文档、通过条数、失败条数、环境（后端地址、health 检查结果；不要写密钥）。
- 一张表：id、问句、期望、实际终态帧、硬条件过/不过、备注。
- 失败条用人话写可能卡在哪（出数 / 澄清 / 拒答 / 执行失败）；不给代码补丁，不把完整返回体粘进报告。
