# 指标 / 数据约定大纲（metrics-dictionary）

> 版本：v0.2（P4 产出，**大纲级**，不是业务代码、不是 DDL；按算法 SDD v0.4 重写）
> 用途：给 ChatBI 第一包数据（电商大促复盘）提供唯一的**业务口径与数据表设计依据**，并提前回答 `docs/测例.md` 点名要在 SDD 阶段确认的三件事：**AOV 口径唯一、T09 美妆歧义、T07/T08 时间维度**。
>
> **v0.2 相对 v0.1 的范式变化**：本文件不再是"平台可答范围的授权闸门"。新链路下——
> - **L0（必需、总有）**：dw 库真实表结构（表/列/类型/主外键/**中文列注释**/枚举采样），api 启动时自动抽取；**可答边界＝已接入数据库**，没有任何字典文件冷启动即可跑 T01～T15；
> - **L1（可选增强）**：口径公式、别名/歧义组、time-calendar、S2 模板、exemplar 示例，放在 `algorithm/resources/` 与 app.exemplar 表；有则更准，无则算法基于 L0 + 列注释硬跑，期望结果不变；
> - P6 据此产出两批东西：**必需的** `backend_service/db/` dw DDL + seed（L0 来源）；**可选的** `algorithm/resources/dict/*.yaml`、`templates/*.yaml`、exemplar seed（增强，可后置）。字段级说明届时另出 `docs/数据字典.md`。
>
> 本文件改动 = 业务口径或第一包数据变更，先改文档再改 DDL/seed/资源。

---

## 1. 两层定位回顾

- 算法能答什么，**由已接入 dw 库中真实存在且可对齐的表/列决定**（L0），不由模型猜表，也不由一份白名单文件授权（链路见 [SDD-算法应用.md](./SDD-算法应用.md) §1、§7）。
- 第一包数据内容：**4 个指标 + 5 类维度 + 一包档期日历 + 6 张 dw 表**。"品牌心智份额"等已接入表中无对应数据的问法 → S4 `not_answerable(NO_MATCHING_DATA)`（T10）；归因/预测 → S1 `not_answerable(NOT_DATA_QUESTION)`（T15）。
- 电商大促复盘是第一包数据；扩指标/换行业 = 加 dw 表/seed（必需）+ 加 L1 资源（可选）+ 加测例，不改链路。

## 2. 指标（本版唯四，业务口径写死）

口径本身写死在本文件；运行时是否"锁定"取决于 L1 是否配置（见每条规则）。

| id | 业务名 / 常见别名 | 唯一定义 | 单位/格式 | 支持的维度（粒度上限） | seed 核对参考区间 |
|---|---|---|---|---|---|
| `gmv` | GMV / 成交额 / 销售额 | **支付状态订单的商品成交金额合计**（不含运费；**不扣退款/退货**，退货由退货率单独刻画） | 元，2 位小数 | 渠道、类目、新老客、档期、日期（日及以上）、整体 | ≥ 0 |
| `conversion_rate` | 转化率 / 支付转化率 | **支付买家数 ÷ 访客数 × 100%**（买家数按去重客户计；访客数取流量事实 UV） | %，1 位小数 | 渠道、日期、档期、整体。**本版不支持类目粒度**（无类目级流量分母）；问到 → S4 `CALIBER_CONFLICT` 拒答并建议渠道口径 | 0～100% |
| `return_rate` | 退货率 | **退货商品成交金额 ÷ GMV × 100%**（金额口径；退货归属到原订单的统计周期） | %，1 位小数 | 渠道、类目、档期、日期、整体 | 0～100% |
| `aov` | 客单价 / AOV | **GMV ÷ 支付订单数**（测例备注二选一拍板：取订单数，不取付款人数） | 元，2 位小数 | 渠道、新老客、档期、日期、整体 | ≥ 0 |

口径规则：

1. **有 L1**：`resources/dict/metrics.yaml` 给出公式、口径过滤（如 `pay_status='已支付'`）、来源表/列，作为 S3 召回上下文供 Aligner 对齐、Coder 生成；**无 L1**：Aligner 基于 L0 列名与中文列注释推断，且必须把实际采用的口径在 `caliber.summary/detail` 中明示（T06 铁规则：AOV 分母必须显式给用户看到）；
2. 类目粒度 GMV/退货率走订单明细金额（明细金额合计与订单 GMV 在 seed 中可对账）；
3. 指标不支持的维度组合（如类目转化率）= 口径自相矛盾，S4 出 `not_answerable(CALIBER_CONFLICT)` + suggestions（引导到渠道口径），**不到执行期才报错**；
4. 表中"核对参考区间"是 **seed 造数与人工核对标准**，不是运行时闸门——新链路没有数据质量拦截节点，异常值不出系统错误。

## 3. 维度（L0 物理列 + L1 别名增强）

| id | 业务名 | L0 物理来源（P6 落表） | L0 无字典时怎么被识别 | L1 可选增强 |
|---|---|---|---|---|
| `channel` | 渠道 | dim_channel.channel_name | 列注释 + 枚举采样（渠道 A/B/C/D） | 别名组：平台、流量渠道 |
| `category` | 类目 | dim_category（两级：level1_name / level2_name，事实挂 leaf） | 层级外键 + 两个名称列的枚举采样 | 别名/歧义组（见 3.1）、实体组（如江浙沪，本包不用） |
| `date` | 日期（日） | dim_date.date / fact 表日期列 | 日期类型列 + 注释；档期词无 L1 日历时按日期列分布推断 | time-calendar（见第 4 节） |
| `promo_phase` | 档期 | dim_date.promo_phase | 枚举采样：预热/正式/返场/日常 | 命名区间在 time-calendar 精确化 |
| `customer_type` | 客户类型 | fact_order.is_new_customer | 布尔列 + 注释（新客/老客） | 展示名映射 |

排序/限幅：TopN（T04/T14）由 S4 `QuerySpec` 的排序/limit 表达，S5 lint 注入 LIMIT；默认限幅 500 行、硬上限 1000，触达置 `truncated`（配置在后端 `ROW_LIMIT_DEFAULT/MAX`）。

### 3.1 T09「美妆」歧义怎么落（L0 数据本身触发，L1 只增强）

**必需（L0 seed 责任）**：dim_category 的真实枚举值里就让"美妆"一词命中多个候选，S3 枚举采样、S4 对齐时不依赖任何配置文件即可发现一对多，例如：

```text
枚举采样中「美妆」的多个候选（真实存在于 dim_category 数据行）：
  ① level1_name = 美妆个护          （一级类目整体，含其下全部二级）
  ② level2_name = 彩妆              （美妆个护下二级类目）
  ③ level2_name = 护肤              （美妆个护下二级类目）
  ④ level2_name = 美妆工具          （名称含"美妆"但归属/范围不同，单列为候选）
```

**可选（L1 增强）**：`resources/dict/category.yaml` 维护歧义组（把"美妆/美妆类/ beauty"等等价说法归一到上述候选），只提升召回与选项文案质量。

S4 命中多候选且无法自行消歧 → `action=clarify`，`reason_code=METRIC_DIM_AMBIGUOUS`，options 即候选值（文案业务化），确认前不出数；确认后拼 clarified_question 从 S1 重入。**新增歧义值 = 加数据行（必需时）+ 可选改 YAML，不改代码。**

## 4. 时间与档期日历（T07/T08/T11 的依据）

### 4.1 主切片：2026 年 618（命名区间写死在本文件）

| 命名 | 绝对区间 | 用途 |
|---|---|---|
| 本期大促·预热期 | 2026-06-01 ～ 06-15 | 档期维度（T11） |
| 本期大促·正式期（"大促三天"） | 2026-06-16 ～ 06-18 | T01/T03/T05 等"大促期间/大促三天" |
| 本期大促·返场期 | 2026-06-19 ～ 06-20 | T11 |
| **大促期间（整体命名区间）** | **2026-06-01 ～ 06-20** | T01/T11 不带阶段词的"618 大促期间"；T07 中段 |
| 大促前一周 | 2026-06-09 ～ 06-15 | T07 A 段（与预热末日重叠是真实日历如此，结果中按标签呈现） |
| 大促后一周 | 2026-06-19 ～ 06-25 | T07 C 段 |
| 去年同期（同比） | 2025-06-16 ～ 06-18 | T08 |

规则：

1. 用户说"618/大促"且无年份 → 默认 2026 本期；"大促期间"默认整体命名区间 6/1–6/20；明确说"三天/正式期"取 6/16–6/18。**有 L1 time-calendar 时直接查配置；无 L1 时 Aligner 按常识与日期列分布归一到绝对日期，并在口径摘要中明示推断结果**（与测例说明一致）；
2. 缺时间且无法默认（如问"各渠道 GMV 怎么样"无档期词、上文也无）→ S4 出 `clarify(MISSING_TIME)`，input_type=time_quick，给"本期大促 / 最近 7 天 / 自定义"；
3. **数据覆盖声明**：seed 覆盖 **2025-06-01 ～ 2026-06-30**，其中 2025 年仅保证 618 同期窗口（6/1～6/25）有数；同年其他月份或 2024 年的同比请求 → S4 `not_answerable(NO_MATCHING_DATA)` 并给可答替代（建议环比/本期）；
4. "环比"无当前周期语境（无上文、无档期默认）→ 澄清选周期（`MISSING_TIME`）；档期三段对比（T07）由 S4 挂 `ComparisonSpec{mode:mom/custom, periods: 三段绝对区间}`（算法 §4）。

## 5. 数仓表集大纲（dw schema，L0 核心，P6 必需产出）

最小 6 张表（3 维 + 3 事实），只经 chatbi_ro 只读角色消费；它们同时就是算法 lint 的 L0 表白名单来源。

| 表 | 粒度 | 关键字段（大纲） | 支撑测例 |
|---|---|---|---|
| `dim_date` | 日 | date, year, month, day, promo_phase, is_promo, promo_relative_week | 全部时间归一、T03/T07/T08/T11 |
| `dim_channel` | 渠道 | channel_id, channel_name | T01/T02/T03/T12 |
| `dim_category` | 叶子类目 | category_id, level1_id, level1_name, level2_name | T04/T05/T09/T14 |
| `fact_order` | 一单一行 | order_id, customer_id, channel_id, order_date, is_new_customer, pay_status, gmv_amount | GMV/AOV/转化率分子/新老客：T01/T06/T13 |
| `fact_order_item` | 一单内一商品行 | order_id, item_id, category_id, paid_amount, qty, is_returned, return_amount | 类目 GMV、退货率：T04/T05/T14 |
| `fact_traffic_daily` | 日 × 渠道 | date, channel_id, visitors | 转化率分母：T02 |

DDL/seed 硬要求（L0 是无字典模式的全部依靠）：

1. **每张表、每个业务列必须写中文 `COMMENT`**：无 L1 时 Aligner/Coder 对指标口径、列含义的判断全部来自列名 + 注释 + 枚举采样；注释质量直接决定无字典模式能不能跑通；
2. 枚举值用业务可读中文（渠道 A/B/C/D、预热/正式/返场/日常、已支付/已退款 等），让 L0 枚举采样本身就能支撑"美妆多候选""档期切分"；
3. seed 要求（P6 Done 标准之一"数据有故事"，固定随机种子、多环境可复现）：渠道 A GMV 领先且占比清晰可讲；美妆相关类目退货率明显高于 8%（T05 判定有方向）；日粒度有起伏（T03/T12 折线有内容）；2026 vs 2025 同比有明确方向和非零差值（T08）；新老客占比不极端（T13）；
4. 不建 SKU 库存表（PRD/测例 Out：T14 只到类目 TopN）；
5. 运营资源即**活动档期日历**：dim_date 的档期列 + 本文件 §4.1 命名区间（T11），描述性呈现"各档期 GMV"，不做归因；本版不接第二张运营资源表。

## 6. L1/示例资源清单（可选增强，P6 可后置）

均不阻塞主链路；**全部缺失时 T01～T15 的期望结果不变**，只是精度/召回/速度降级。

| 资源 | 位置 | 内容 | 缺省时的降级 |
|---|---|---|---|
| 指标口径字典 | `algorithm/resources/dict/metrics.yaml` | 4 指标公式、口径过滤、来源表列、单位格式（即 §2 口径） | Aligner 依列名/注释推断，口径在 caliber 明示 |
| 维度别名/歧义组 | `algorithm/resources/dict/category.yaml` 等 | 「美妆」歧义组、别名（平台/流量渠道）等 | L0 层级 + 枚举采样触发澄清（§3.1），召回面更窄 |
| 档期日历 | `algorithm/resources/dict/time-calendar.yaml` | §4.1 全部命名区间、数据覆盖声明 | Aligner 按日期列分布/常识推断并明示 |
| S2 模板皮肤 | `algorithm/resources/templates/*.yaml` | 高频问法骨架 + 槽位 + SQL 模板 + 图型（如 `{time}各渠道 GMV`，T01 可命中快路径） | 空库 → S2 永远未命中，全程走 S3→S4→S5 |
| 示例库 | app.exemplar 表（pgvector，后端迁移建表） | (问法, SQL, 图型, 标签) 典型示例如 ranking/pie/对比写法 | S3 不召回示例，Coder 只靠 L0/L1 上下文生成 |

示例与模板录入本版靠初始化管理命令/seed；exemplar 的 embedding 写入仅在 `EMB_*` 配置齐全时进行，未配置时表可不存在、S3 自动 `mode=lexical`。

## 7. 给各分册的约束回执

- **算法**：指标唯一定义、维度粒度上限、美妆多候选、档期命名区间与数据覆盖以本文件为准；S3 中 L0 必有、L1 四类可选；S4 负责口径对齐（无 L1 时口径必须明示）、类目级转化率出 `CALIBER_CONFLICT`、超数据覆盖出 `NO_MATCHING_DATA`、缺时间出 `MISSING_TIME`；S5 lint 表白名单＝L0 抽取出的这六张 dw 表；S8 解读只用真实行数字；
- **后端**：`backend_service/db/` 初始化 SQL 建六张 dw 表（含中文 COMMENT）与 seed；`RESOURCES_PATH` 下 dict/templates 可缺省；chatbi_ro 仅 SELECT；限幅 500/1000；
- **前端**：业务列名/单位/格式（元 2 位、率 1 位小数、千分位）按本文件渲染；对比"不可比"原样呈现；
- **测例**：本文件直接回应三条待确认项——AOV＝GMV/**支付订单数**（T06 口径摘要明示）；美妆歧义由 L0 类目层级/枚举多候选触发、L1 仅增强（T05/T09）；档期与同比区间按 §4.1、无 L1 日历时推断并明示（T07/T08）。
