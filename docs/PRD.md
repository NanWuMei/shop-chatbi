# PRD · ChatBI 通用对话式数据分析平台

> 版本：v1.0（P3 产出）
> 本文只写产品需求与交互，不写技术架构、Agent 拆分、数据表结构与资源接入方式（属后续 SDD）。
> **两层结构**：第一层是产品本身——通用 ChatBI 平台（平台策略只由这一层决定）；第二层是首个验收切片——电商大促复盘（仅证明问数能力落地，不构成平台边界，见第 5 节）。换行业、换岗位，换的是接入的数据与业务含义（指标、维度、口径），不是换产品。
> 名词约定：**口径**＝这次查询到底在算什么（指标定义、维度、时间范围、筛选）；**结果卡片**＝一次问数的完整产物（一句解读＋图表＋数据表＋口径摘要）；**报表**＝口径确认后保存下来、可重复打开的结果。

---

## 1. 产品概述

ChatBI 是一个**打开网页就能实际用的通用对话式数据分析平台**：用对话问数，出表、出图、出一句业务解读；口径不清会先追问、不该答的会拒答；确认无误的结果可以一键存成报表，以后从报表入口直接打开看，不用再问一遍。

两个同时成立的产品判断：

1. **对话问数是入口，不是全部**。问数 → 确认 → 沉淀为报表 → 反复查看，形成闭环，不是一问一答的玩具。
2. **它不是完整商业化 BI 中台**。不做自由搭建仪表盘、报表编排分发、权限中台、计费；能力主线是"业务同学自助问数 ＋ 结果沉淀复用"。

---

## 2. 目标用户

- **主要用户**：要看数、要做分析的业务同学——不写 SQL、不等数据排期，想用自然语言拿到数据和结论的人。
- 使用前提：了解自己业务里的指标说法，但不需要懂技术。
- 本文不把任何单一岗位（如"大促复盘官"）写成唯一用户；岗位与行业只影响接入的业务含义，不影响平台功能。

## 4. 功能交互明细

> 每个功能写清：**从哪进 → 用户怎么操作 → 系统怎么反馈 → 确认/取消怎么办 → 失败或空数据怎么办**。

**页面与入口（公共说明）**：单页网页，主导航含「问数」「报表」「对话记录」三个入口；首次打开默认进入「问数」；入口间切换不丢当前对话状态。本版无登录态（见 4.8）。

### 4.1 F1 对话问数（含过程可见、结果呈现、多轮追问）

**从哪进**：主导航「问数」。上部为对话消息流（用户问题、过程消息、澄清卡片、结果卡片依次出现），底部为输入框＋发送按钮；输入为空时发送置灰；回车发送、Shift+回车换行。

**怎么提问**：
1. 输入具体的自然语言问题（如"618 大促期间各渠道 GMV 是多少，按从高到低排"），发送后问题以气泡进入消息流。
2. 支持在同一对话里多轮追问（如拿到结果后说"按天展开看看"），系统承接上文口径，用户不必重述条件。
3. 问题过于空泛（如"分析一下经营情况"）按澄清处理（4.2），平台给出可点的具体问法方向，不自由发挥；输入超长时提示缩短或拆分。

**怎么看到对话过程（过程可见、可取消）**：
- 发送后出现过程状态，依次显示"正在理解问题 → 正在核对口径 → 正在取数"。
- 过程中提供「取消」：点击后本次问数终止、标记"已取消"，不留半成品结果。
- 理解完成后三种走向：口径清晰→结果卡片；有歧义/缺条件→澄清卡片（不出数）；不可答→拒答消息（不出数）。

**结果区怎么出表/图/一句解读（结果卡片，自上而下）**：

| 区域 | 内容 |
|---|---|
| ① 一句业务解读 | 与数据一致的一句话口语化结论（如"渠道 A 的 GMV 最高，占全渠道约 42%"）。**只一句**，不写多步分析、不写追投建议 |
| ② 图表 | 按问题自动选型：比较→柱状图、趋势→折线图、占比→饼图；右上角可手动切换为其他合适类型 |
| ③ 数据表 | 图表对应明细，列名用业务名称；数据量大时分页/限幅并明示"仅展示前 N 行" |
| ④ 口径摘要 | 默认折叠一行：指标＋维度＋时间范围＋筛选；点"查看口径"展开全文，供用户核对 |
| ⑤ 操作区 | 「存为报表」（进入 4.5）、「口径不对，重新澄清」 |

- 解读、图表、数据表三者数字必须同源一致；解读不得出现数据中没有的数字；图表悬浮显示具体数值。
- 点「口径不对，重新澄清」→ 基于原问题生成澄清卡片，原结果卡片保留为历史。

**失败或空数据**：取数失败/超时显示提示＋「重试」，不返回半截数据、不编造结果；查询成功但无数据时显示"该条件下暂无数据"＋口径说明＋「放宽条件再试」，这是正常结果而非报错，不用 0 或空表伪装；图表渲染失败时数据表与解读正常展示，此时「存为报表」置灰。

### 4.2 F2 澄清（口径不清，先问后算）

**什么时候追问（满足任一即澄清，不出数）**：
1. 指标/维度有多种可能含义（如"美妆"在已接入类目数据中对应多个口径）；
2. 缺必要条件：时间范围缺失且无法从上下文确定，或必选筛选缺失；
3. 问题空泛、落不到具体指标；
4. 多轮追问中指代不明（"那个渠道"但上文无渠道语境）。

**追问长什么样（澄清卡片）**：
1. 标题说明在确认什么（如"请确认类目口径"）。
2. 按歧义类型给可选项：单选歧义给按钮式单选项；缺时间给快捷选项（本期大促/最近 7 天/自定义）；空泛问题给 2～4 个具体问法按钮，点选即发送。
3. 底部「确认并查询」（未选择前置灰）与「取消」；另提供"我换个问法"输入入口。

**确认/取消**：选择后点「确认并查询」→ 带确认口径继续取数出结果卡片；点「取消」→ 卡片收起标记"已取消澄清"，不出数。**铁规则：用户确认前绝不输出数据和解读。** 二次回答仍无法确定口径时允许再追问一次；连续两次仍不能确定，转为拒答（4.3 第 5 类），不无限追问。

### 4.3 F3 拒答（不该答的明确拒，不许编数）

**什么时候拒（满足任一即拒）**：
1. 问了已接入数据中没有的指标/字段（如"品牌心智份额"）；
2. 所需数据未接入；
3. 与数据问数无关的闲聊或其他任务；
4. 要求平台不具备的能力：归因/因果、趋势预测/推演（可呈现数据事实，不产出因果结论与预测值）；
5. 经澄清仍无法确定口径。

**怎么说明原因**：
1. 明确说不能回答，并用大白话说明属于哪类原因（没这个指标／数据没接／这类问题平台不算／口径没法确定）。
2. 给引导：列出确实可问的相关指标或问法按钮，点击即作为问题发送。语气是"这个答不了，但你可以这样问"，不暴露报错代码。
3. 归因类问题降级为："我不算原因，但可以给你相关数据"，附对应数据问题按钮；用户点了才出数据，不擅自把数据当原因。

**铁规则**：拒答是终态——不出表、不出图、不出解读，不提供"仅供参考"的假数据，**绝不编数**。

### 4.4 F4 对比（同比 / 环比 / 前后时段）

**怎么问（三种问法等效）**：
1. 同比："今年 618 GMV 比去年同期高还是低"；
2. 环比："大促期间 GMV 环比大促前一周变化多少"；
3. 自定义前后时段："6/1–6/10 和 6/11–6/18 的 GMV 对比"。

**口径处理**：对比周期说不清（只说"环比"而无当前周期语境）→ 走澄清让用户选周期；去年同期数据未接入 → 走拒答第 2 类，说明数据未接入并给可答的替代问法（如今日环比）。

**结果怎么呈现（对比专用版式）**：
- 数据表：双方数值并列两列，附"变化值""变化率（%）"两列。
- 图表：含时间趋势用双折线图，否则用双系列分组柱状图。
- 一句解读：只陈述事实方向与幅度（如"GMV 同比增长 18.3%"），不解释原因、不给建议。
- 确认后同样可走 4.5 存为报表。

### 4.5 F5 一键成报表

**前置硬门槛**：只有口径已定、正常生成结果卡片时才能存；**澄清进行中、拒答、无数据、取数失败的结果一律不能存**（「存为报表」置灰，悬浮提示原因，如"请先完成口径确认"）。

**从哪进 / 怎么操作**：
1. 在结果卡片操作区点「存为报表」，弹出保存弹窗。
2. 弹窗含：报表名称输入框（按问题预填可读名，如"618 各渠道 GMV 排行"，可改、不可为空）；只读的口径摘要与图表缩略预览，供最后核对。
3. 底部「确认保存」「取消」。同名时提示"已有同名报表"，可选「覆盖」「换个名字」「取消」。

**系统反馈 / 确认取消**：确认后弹窗关闭，消息流出现"已存为报表：〈名称〉"，带「去报表列表查看」链接；取消则不保存、卡片保留。保存动作即视为用户对口径的确认，保存内容为：确认过的口径＋呈现方式（图表类型、表结构）＋当时的解读。

**保存后从哪找到**：主导航「报表」入口的列表中可见（交互见 4.6）。

### 4.6 F6 已存报表管理（列表 / 打开 / 改名 / 删除）

**从哪进**：主导航「报表」。列表按保存时间倒序，每条显示报表名称、创建时间、口径一句话摘要；顶部提供按名称搜索（本版只做名称匹配）。

**打开（再打开就是看报表，不用再问）**：
- 点击报表名称/卡片 → 直接呈现报表名＋一句解读＋图表＋数据表＋口径摘要，布局与保存时一致；**全程不重新提问、不再走澄清**。
- 页面显示口径对应的时间范围与数据时间，让用户知道看的是什么时候的数据。
- 提供「刷新」：按原口径重新取数看最新值，不改变报表定义；提供「基于这个问题继续问」：携带口径跳回「问数」页作为新追问起点，不影响报表本身。
- 打开时取数失败：保留报表定义与口径，数据区显示"加载失败＋重试"，不用空白页、不拿旧数字冒充新数字；刷新后无数据：显示"当前口径下暂无数据"并保留口径与"调整问题继续问"入口。

**改名**：每条报表「改名」入口 → 名称变可编辑框 → 回车/「确认」生效，Esc/「取消」放弃；空名拦截并提示。

**删除**：点「删除」→ 二次确认弹窗"确定删除报表〈名称〉吗？删除后不可恢复。" → 「确认删除」后移出列表并提示，「取消」则保留。

**失败处理**：改名/删除操作失败时列表保持原状并提示"操作失败，请重试"，不允许"点了没反应"。

### 4.7 F7 对话记录

**从哪进**：主导航「对话记录」。

**能看到什么**：按时间倒序展示历史会话，每条显示首个问题（作标题）、最近提问时间、问答条数。

**怎么操作**：
- 打开：点击进入当时对话页，消息流（含澄清卡片、结果卡片）完整还原，可在输入框继续追问，上下文沿用该会话。
- 删除：单条会话删除，二次确认，交互同报表删除。

**本版边界**：只记录并展示本环境上的历史；跨设备同步、会话全文搜索、收藏/置顶本版不做（见第 7 节）。

### 4.8 F8 登录鉴权 / 多用户权限（平台该有，本版演示暂缓）

**平台定位（明确写出，不回避）**：平台正式形态应具备用户登录、会话归属（谁的对话、谁的报表）、多用户数据与报表隔离，以及后续对接数据权限的能力——这是平台能力的一部分。

**本版演示处理（明确标注暂缓）**：
- 本版不做登录页、不做账号体系、不做多用户权限与隔离；按"单用户、本地演示环境"直接可用处理，报表与对话记录均为单一空间、不区分归属人。
- 不把产品写成"永远不需要登录"；完整权限中台能力（角色、行列级数据权限、审批）不在本版、也不在平台近期范围（见第 7 节）。

### 4.9 F9 可部署

**用户可观察的形态**：通过 Docker Compose 启动服务后，在浏览器打开对应地址即可使用本版全部功能（问数、澄清拒答、对比、存报表、报表管理、对话记录），无需安装客户端、无需命令行操作；首次打开默认进入「问数」页。

**本版范围**：一套 Docker Compose 可在本地/演示环境拉起并在浏览器打开即视为满足；具体拓扑、镜像、配置属 SDD，不在本 PRD 展开。K8s、生产级 CI/CD 不做（见第 7 节）。

## 5. 首个验收切片：电商大促复盘

- **定位**：这是平台落地的**第一包问数演示与评测场景**，用来证明通用问数能力在一个具体业务里跑得通；**不构成平台边界**，不定义"平台给谁做、只能干什么"。
- **内容**：以 618 大促复盘为镜头，使用电商业务含义（GMV、转化率、退货率、AOV、渠道、类目、档期）问数。
- **接入前提**：只需接入电商数据表即可问数，**不要求预配业务字典/语义层**——平台基于已接入表的库结构作答；业务字典、示例等资源仅作增强（有则口径更准、澄清更稳），无则降级可跑，全部测例的期望结果不因此改变。
- **问数演示与评测**：直接引用 `docs/测例.md`，以该文件为准，**不另起一套问数题**；其中澄清、拒答、对比、多轮、运营资源类用例同样用于验证 F1～F4。
- **报表类平台功能不塞进问数测例**：F5/F6 的验收用第 9 节的可观察标准单独走。
- 对具体人群、细分场景的进一步支持（如某岗位专属看板）留给后续应用层方案，本 PRD 不展开。

## 6. 用户故事

> 主语统一为"业务同学/用户"，不锁岗位。问数类锚定 `docs/测例.md` 用例；报表类按第 4 节交互验收。

1. **直接问数拿到完整结果**：我直接问"各渠道 GMV 排行"，系统一次给出表、图和一句解读，不用写 SQL、不用等排期。（锚 T01）
2. **口径不清被追问而不是被乱答**：我的说法有歧义时，系统先让我选清楚口径，确认后才出数，避免拿到"看似对其实算错"的结果。（锚 T09）
3. **超范围被明确拒绝并被引导**：我问了平台没有的指标或要求归因/预测时，系统直说答不了、说明原因，并建议确实能问的问题，绝不编数。（锚 T10、T15）
4. **做同比/环比对比**：我能用自然语言问同比、环比或任意两个时段的对比，拿到并列数值、变化率、对比图和一句方向性解读。（锚 T07、T08）
5. **在上下文里继续追问**：拿到结果后我直接说"按天展开看看"，系统基于上文继续答，不用重说条件。（锚 T12）
6. **把确认过的结果沉淀成报表**：核对口径无误后，我一键把结果存成报表并命名，以后不必重复问同一个问题。
7. **从报表入口直接看数**：我从报表列表打开已存报表，不经过重新提问和澄清，直接看到表、图、解读和口径；需要最新数时手动刷新。
8. **管理我的报表与历史**：我能改名、删除报表，也能在对话记录里找回以前问过什么并继续问。

## 7. 需求范围（In / Out）

### 7.1 In（平台该有的能力）

| 能力 | 对应功能 | 本版演示 |
|---|---|---|
| Web 对话问数：自然语言提问，返回表/图/一句解读，含多轮追问、过程可见可取消 | F1 | 演示要有 |
| 澄清：歧义/缺条件/空泛/指代不明时先追问，确认前不出数 | F2 | 演示要有 |
| 拒答：无此指标、数据未接、闲聊、归因预测、口径无法确定 | F3 | 演示要有 |
| 对比：同比、环比、自定义前后时段 | F4 | 演示要有 |
| 口径确认后一键存为报表 | F5 | 演示要有 |
| 报表直接打开查看、刷新、基于报表继续问，以及列表/改名/删除 | F6 | 演示要有 |
| 对话记录：列表、还原、继续、删除 | F7 | 演示要有 |
| 登录与身份、数据归属隔离（平台能力位） | F8 | **可暂缓** |
| Docker Compose 可部署、浏览器打开即用 | F9 | 演示要有 |

> In 只描述平台能力，不把电商场景细节（档期、活动、类目等）膨胀成平台通用功能；那些属于本包接入的业务含义。

### 7.2 Out

**平台边界外（完整 BI 中台类重能力，产品不做）**：
- 自由拖拽式仪表盘/大屏搭建、多组件布局编排；
- 报表定时调度、邮件/IM 订阅与分发、审批流；
- 复杂归因、因果推断、趋势预测与推演；
- 跨数据源/跨工具取数（外部文档、聊天工具等）；回答范围以**已接入的数据库**为界，未接入的数据明确拒答；
- 行列级细粒度权限中台、多租户、组织角色体系、计费；
- 通用聊天及与数据无关的任务。

**平台要做、但本版演示暂缓**：
- F8 登录/登出/会话保持、多用户身份与数据隔离；
- 报表与对话的跨设备同步、会话全文搜索、收藏置顶；
- K8s 与生产级 CI/CD（本版 F9 以 Docker Compose 为界）。

## 8. 平台通用规则（先问或拒、确认后再存）

1. **范围不清先问或拒，绝不猜**：口径可澄清时走 F2 追问；不可答时走 F3 拒答；任何情况下不得在口径未确认时输出结果。
2. **确认前不出数、确认后才存报表**：澄清未闭环、拒答、无数据、取数失败的结果不可保存（F5 按钮置灰）。
3. **不许编数**：拒答不出任何数字；失败不出半截结果；空数据不用 0/空表伪装；解读只引用本次结果中存在的数字。
4. **解读永远只一句**：陈述数据事实，不做归因、不做预测、不写行动建议。
5. **数字一致性**：解读、图表、数据表同源一致。
6. **过程可中断、失败可重试**：取数可取消（不留半成品）；失败/超时给重试；空数据给说明与放宽建议。
7. **业务语言优先**：指标、维度、列名一律用业务说法，不向用户暴露技术细节。

## 9. 验收标准

### 9.1 问数闭环（引用 `docs/测例.md`，不另起题库）
- 取数/对比类：结果卡片含一句解读＋图表＋数据表，数字正确、三者一致。
- 澄清类（如 T09）：必须先出澄清卡片，用户确认前不出数。
- 拒答类（如 T10、T15）：必须拒答、说明原因、给可问建议，且无任何编造数字。
- 对比类（如 T07、T08）：含并列数值、变化值/率、对比图与一句事实性解读。
- 多轮类（如 T12）：承接上文、指代正确。
- 过程状态可见、可取消。

### 9.2 报表沉淀与管理（F5/F6，可观察、可逐条打勾）
1. 正常结果卡片可点「存为报表」，弹窗可改名、可见口径与图表预览，确认后出现成功提示与列表入口。
2. 「报表」列表出现该报表，名称、时间、摘要正确。
3. 打开报表**不经过重新提问和澄清**，直接呈现与保存时一致的表、图、解读、口径。
4. 报表可刷新；刷新失败/无数据有对应提示且不伪造数字。
5. 改名即时生效；空名被拦截。
6. 删除有二次确认，确认后消失、取消则保留。
7. 同名保存出现"覆盖/换名/取消"选择。
8. 「存为报表」在澄清中、拒答、无数据、失败状态下均置灰不可点。

### 9.3 对话记录（F7）
9. 列表可见历史会话（首问标题、时间、条数），打开后消息流完整还原并可继续追问。
10. 会话可删除（二次确认）。

### 9.4 部署（F9）
11. Docker Compose 启动后，浏览器打开地址即可使用上述本版功能，无需安装客户端。

### 9.5 暂缓项确认（F8）
12. 本版不出现登录页与权限交互，界面按单用户环境工作，同时第 4.8 节保留其平台定位说明。

## 10. 产品成功标准

以下四件事在网页上**同时成立**，产品才算做成（标准落在平台能力上，不以"服务好某岗位/某次大促"衡量；电商大促复盘只是证明平台能力成立的第一包切片）：

1. **问得出、答得对**：业务含义范围内，问一句拿到表＋图＋一句解读，数字一致、口径可查（9.1 取数类用例通过）。
2. **该问会问、该拒会拒**：口径不清先澄清、确认前不出数；超范围/归因预测时拒答并引导，全程不编数（9.1 澄清拒答类用例通过）。
3. **比得了**：同比、环比、前后时段可问、可呈现。
4. **沉得下、开得回**：确认口径后一键存报表；从报表入口打开即直接查看、无需再问；报表可管理（9.2 全部打勾）；服务可经 Docker Compose 部署、浏览器打开即用（9.4）。
