## 1. 垂直故事
### 主故事（推荐）：电商「大促复盘官」（运营分析师）
| 维度 | 设定 |
| ---- | ---- |
| 角色 | 电商运营分析师 / 大促复盘官，隶属商家或品牌运营中台 |

## 2. 定向调研
调研深在「交互与能力边界」决策点，不写行业长文，不列融资/市占率。覆盖 3 个参考：ThoughtSpot Spotter（原 Sage）、Snowflake Cortex Analyst、网易有数 ChatBI。信息不确定处标注「待核实」。

### 2.1 ThoughtSpot Spotter（原 ThoughtSpot Sage）
- **名称与类型**：产品 — 企业级对话式 BI（SaaS）。原 Sage 已 EOL，自动升级为 Spotter（2/3 代）。
- **交互要点**：
  1. 搜索框式自然语言提问，plain English → 生成 SQL → 在 live 数据上执行，返回图表/答案。
  2. Spotter 3 走多步 Agent：制定计划 → 校验假设 → 自我修正 → 给可验证结果；支持多轮追问（follow-up），并可在对话中跨工具拉数据（Slack/Confluence 等）「待核实：跨工具拉数据为 Beta/EA，具体可用范围」。
  3. Answer Explainer：给出数据血缘 / 搜索 token，展示数字从哪来、怎么算的。
  4. Spotter Shortcuts：用 `@` 选列/筛值，自然语言 + 精确输入混合，降低错配。
  5. SpotterViz Insight tiles：AI 生成文本解读（从一句到多步分析），随数据刷新。
  6. human-in-the-loop 治理：可批准/修正 AI 答案，thumbs up/down 反馈让系统越用越准。
- **能力边界要点**：
  1. 强调：基于 governed semantic model / data model，不裸跑 schema 直问。
  2. 强调：data-aware intelligence，只把回答问题所需的数据送 LLM，不存不训。
  3. 明确不碰：不做通用闲聊；Sage 已 EOL 收敛为 Spotter（说明产品在收敛对话式 BI 形态）。
  4. 强调可验证、可追溯（lineage / 数据血缘）。
- **可借鉴到本 MVP 的点**：
  1. 「Answer Explainer」思路：结果附数据血缘/口径说明，增强可信。
  2. 一句业务解读（narrative insight）作为标配输出。
  3. `@` 精确选维度/筛值 + 自然语言混合，降低模糊提问错配。
- **来源（待核实）**：ThoughtSpot 官方文档/release notes、product/sage 页、Querio 2026 对比文。

### 2.2 Snowflake Cortex Analyst
- **名称与类型**：产品 — 云数据平台内置的 agentic NL2SQL，REST API 优先。
- **交互要点**：
  1. 自然语言 → 语义模型（YAML） → 生成 SQL → 在 Snowflake 执行 → 返回结果。
  2. 支持多轮对话 follow-up；但文档明确限制：不能访问上一轮 query 的结果，跨轮上下文会丢失。
  3. REST API-first，前端可自建 chat（Streamlit / Slack / Teams / 自定义界面）。
  4. 内建 Verified Query suggestions + Evaluations 评测工具。
  5. 自动选模型 / 多模型组合，按查询选最佳组合。
- **能力边界要点**：
  1. 强调：semantic model 是精度核心（官方 BIRD-SQL 基准：同模型 57% → 78% 仅靠加语义层），不裸跑 text2sql。
  2. 明确不碰：不能生成超出语义层的 SQL；不能生成超出 SQL 可回答的 insight；跨轮无法访问上次结果。
  3. 强调：数据不出 Snowflake 治理边界，不训不存；继承 RBAC 行列权限。
  4. 不做通用聊天；定位是「结构化数据的自助问数」。
- **可借鉴到本 MVP 的点**：
  1. 语义层/指标字典是准确率命门 —— MVP 必须先定义指标/维度字典再谈问数。
  2. 明确「不答超出字典/语义层的」—— 拒答边界要清晰、要敢拒。
  3. 内建评测（verified query / golden set）思路，直接对齐本课「可评测」要求。
- **来源（待核实）**：Snowflake 官方 Cortex Analyst 文档、GeekChamp/Atlan/Kaelio/ZenML 评测与案例文。GitLab 案例：简单查询 95~95%、复杂 75%（「待核实：为案例自述口径」）。

### 2.3 网易有数 ChatBI（含观远边界观点补充）
- **名称与类型**：产品 — 国产 BI 的对话问数模块（电商/零售场景贴脸）。
- **交互要点**：
  1. 先选数据表（可多选；多表效果差时减到单表），再自然语言提问 —— 把「范围」前置。
  2. 三类歧义匹配：多成员/多表、跨多字段（提示选字段，可「智能选择」）、可信模式（仅当查询评分日分准确时才答）。
  3. 开启追问（多轮）。
  4. 生成总结（一句解读）。
  5. 结果验证：验证准确性 / 干预问答结果 / 提升准确性（反馈闭环）。
  6. 推荐六类问法（算数值/看趋势/查明细/TopN/做比较/同比环比）+ 知识库参考提问，引导用户提具体可测问题。
- **能力边界要点**：
  1. 强调：基于已配置数据模型/数据表，当前仅稳支持单表查询（多表效果不稳）。
  2. 强调「可信模式」—— 不百分百确定不硬答（一种拒答/澄清机制）。
  3. 不碰：未接入/未定义的数据。观远明确 ——「ChatBI 不是通用聊天机器人，不能对未加工的 raw 数据生成准确结果」。
  4. 能力分层：归因/预测/多步编排只在「专业模式」做，基础问数不做。
- **可借鉴到本 MVP 的点**：
  1. 「可信模式」思路 → MVP 澄清/拒答：口径歧义/超范围/无数据时主动澄清，而非硬猜。
  2. 范围前置（选主题/选表） → MVP 用「指标/维度字典」圈定范围。
  3. 推荐问题 + 六类问法 → 引导用户提具体可测问题，避免「分析一下经营情况」式空泛。
- **来源（待核实）**：网易有数 BI 用户手册（youdata.163.com）、网易数帆《ChatBI—NL2SQL》分享、观远 ChatBI 选型/落地避坑文章。

### 2.4 对本项目的启示
#### 综合三者后，我们更该强调：
1. 语义层/指标字典先于 Prompt —— 准确率命门（Snowflake/ThoughtSpot/观远一致结论）。
2. 主动澄清 + 拒答 > 硬猜 —— 网易「可信模式」、观远「追问还是硬猜」、ThoughtSpot human-in-the-loop 都指向：敢拒、敢问。
3. 结果可追溯/可解释 —— Answer Explainer、数据血缘、口径说明，让数字可信。
4. 一句话业务解读作为标配 —— narrative insight / 生成总结，不只是甩一张表。
5. 内建评测 —— verified query / golden set，对齐本课「可评测」。

#### 更该裁掉的：
1. 跨工具/跨源拉数据（Slack/Confluence/外部附件） —— ThoughtSpot Spotter 3 才做，超 MVP。
2. 归因/因果/趋势预测 —— 网易才放「专业模式」，明确 Out。
3. 全量数据/裸 raw 表直问 —— 三者均不推荐，明确不碰。
4. 多模型自动选择 / 模型后训练全链路 —— 超 MVP。
5. 多租户 / 行列级 RBAC 全链路 —— Out（仅做单租户 demo 级）。

## 3. MVP In / Out
> In/Out 在调研之后写，体现「参考后的裁剪」。每条 In 附「因调研而保留/采纳」依据一句。

### 3.1 In（最小可演示可评测闭环）
| # | In 项 | 依据（因调研而保留/采纳） |
| ---- | ---- | ---- |
| In1 | 自然语言问数（限定指标/维度字典内） | 三者均强调基于语义层/已配置模型，不裸跑 schema |
| In2 | 结果表 + 简单图表 + 一句业务解读 | ThoughtSpot narrative insight、网易「生成总结」一致 |
| In3 | 澄清 / 拒答（口径歧义、超范围、无数据） | 网易「可信模式」、观远「追问还是硬猜」、ThoughtSpot human-in-loop |
| In4 | 至少 1 个运营资源接入示意（推荐：活动日历） | 大促复盘官最常挂「活动」维度，挂活动日历可解释 GMV 归属 |
| In5 | 少量效果评测 case | Snowflake Verified Query/Evaluations、对齐本课「可评测」 |
| In6 | Docker Compose 可部署 | 本课「可部署」验收，平台型工具而非脚本 |

**运营资源推荐项：活动日历**
- 理由：大促复盘官的核心叙事是「大促 GMV 哪来哪去」，活动日历（大促档期/活动类型/参与门店）天然挂在渠道、类目、时段之上，可解释 GMV 归属，比「券」更易与主故事自治；也比「渠道维」更像「运营资源」而非纯维度。备选：券（若需第二条，但 MVP 不强求）。

### 3.2 Out（明确不碰）
| Out 项 | 裁剪依据 |
| ---- | ---- |
| 完整权限中台 / 多租户计费 | 超出最小可演示闭环 |
| 复杂归因 / 因果推断 | 网易才放「专业模式」；MVP 仅做一句解读，不做归因 |
| 生产级模型后训练全链路 | 超 MVP；MVP 用现成模型 + 字典/语义层即可 |
| K8s / 生产级 CI/CD 全链路 | Docker Compose 可部署即满足验收 |
| 跨工具/跨源拉数据（Slack/Confluence/附件） | 仅 ThoughtSpot Spotter 3 才做 |
| 趋势预测 / 推演 | 网易「专业模式」，MVP Out |
| 全量 raw 表 / 裸 schema 直问 | 三者均不推荐，明确不碰 |
| 多模型自动选择编排 | Snowflake 才做，超 MVP |
| 行列级 RBAC 全链路 / 多租户隔离 | MVP 仅单租户 demo 级 |
