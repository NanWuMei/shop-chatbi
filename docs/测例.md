## 测例设计思路
1. **分层能力**：从单纯取数 → 可视化对比 → 业务解读，由基础查询升级到业务结论，覆盖 ChatBI 核心能力。
2. **输出类型全覆盖**：表格、图表、文本解读三类返回形式，验证模型识别输出形式的能力。
3. **边界约束**：全部限定在已接入数据表范围内，规避越界能力（归因、预测等），控制评测范围；并通过 T10/T15 显式测试拒答边界。
4. **业务贴合**：完全贴合电商运营分析师复盘 618 的真实查询习惯。
5. **In 项全覆盖**：T01–T15 覆盖 In1（问数）、In2（表/图/解读）、In3（澄清/拒答）、In4（运营资源），In5（评测集即本文件）；In6 部署不属测例，单独验收。

## Out 边界测试点
- **不做归因/因果**：T15 提问"为什么"，期望拒答或仅给数据、不给因果结论。
- **不做预测**：预测类问题（如"下个月 GMV 会涨吗"）应同 T10 拒答；本套未单列，评测时可追加。
- **不做跨源 / 未接入数据**：本 MVP 单库；跨源问题、已接入表中无对应数据的问题（锚 T10）拒答。
- **不做 SKU 库存**：T14 用类目 TopN 而非 SKU 级，规避库存能力。

## 说明
- T11 依赖运营资源「大促活动日历」，若最终运营资源改选（券/渠道维），T11 需同步改写。
